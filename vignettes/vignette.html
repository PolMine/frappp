Introducing the Framework for Parsing Plenary Protocols (frappp)

Andreas Blätte (andreas.blaette@uni-due.de)

2018-03-26

A workflow to generate XML

In this vignette, we show how to generate an XML document of a plenary protocol. The example chosen is a verbatim record of a short session in UN General Assembly. Due to the structural similarity of all kinds of plenary protocols (including the verbatim records of UN bodies), this example may illustrate the workflow for parsing plenary protocols using .

The parser of the package, i.e. the class is designed to process plain text documents. However, the usual scenario is that the protocol to be processed is available as a pdf document. In order to walk through the steps we usually encounter, we start with turning a pdf document into plain text.

Preparing a plain text file

There is a set of R packages to extract text from pdf documents, namely Rpoppler and pdftools. However, a typical issue with the pdf of plenary protocols is that documents have a two-column layout. To deal with this special kind of situation, we have developed the package . It is not yet available at CRAN, but it can be installed in convenient manner from the GitHub presence of the PolMine Project using the installation mechanism offered by the package.

if (!"trickypdf" %in% installed.packages()[,"Package"]){
  if (!"devtools" %in% installed.packages()[,"Package"]) install.packages("devtools")
  devtools::install_github("PolMine/trickypdf")
}

The class that implements the workflow to process a plenary protocol is the class. It is a class of the R6 class system. The notation of using R6 classes may be somewhat uncommon for many R users. Usually you will know the S3 and the S4 class system. To learn more about R6 classes, consult the vignette of the R6 package, the introduction to the different class systems in Hadley Wickham’s Advanced R Online Book is an excellent entry to understand the notion of reference classes (there is also a hard copy of the book).

Compared to R’s built-in reference classes (RefClass), R6 is more efficient (see the vignette on R6 and Reference class performance tests). But in fact the biggest advantage of R6 is that you can include classes inheriting from the class in other packages than . R6 allows inheritance across packages. This is essential about this package: It is intended to serve as a basis for projects that develop corpora of plenary protocols.

So far so good. Let us instantiate our parser. We will then configure it to process General Assembly verbatim records.

PPP <- PlenaryProtocolParser$new()

Processing the document requires two steps. First, we have to configure the the parser. This means that we supply a set of regular expressions to detect speakers, agenda items and instructions from the stage. Second, we process the individual document.

Configuring the parser

Defining regular expessions to detect speakers

PPP$speakerRegex <- list(
  
  pres = list(
    regex = "^(The\\s+President):\\s*(.+)$",
    fn = function(who, txt){
      c(
        who = who,
        state = "NA",
        role = "presidency",
        position = "presidency",
        text = txt
      )
    }
  ),
  
  sg = list(
    regex = "^(The\\sSecretary-General):\\s*(.+)$",
    fn = function(who, txt){
      c(
        who = who,
        state = "NA",
        role = "secretary-general",
        position = "secretary-general",
        text = txt
      )
    }
  )
  
)

PPP$speakerMismatch <- character()

Define regular expressions to detect calls for agenda items

Detecting calls to agenda items is optional. The body of a document can also be created with $makeBody(agendaItems = FALSE). For detecting agenda item calls, define the field as a named character vector of (alternative) regular expressions that will match a call to an agenda item.

PPP$agendaItemRegex <- c(any = "^Item\\s+\\d+\\sof.*agenda.*$")
PPP$agendaItemTypes <- c(any = "debate")

Define regular expressions to detect stage instructions

To markup stage instructions, such as interjections, supply a named character vector with regular expressions. In the document that is generated, the value of the attribute of the element surrounding what has been matched will be the name of the regular expression.

PPP$stageRegex <- c(
  end_of_session = "^\\s*The\\s+meeting\\s+rose\\s+at\\s+\\d+\\s[ap]\\.m\\.\\s*$"
)

Processing a Protocol

We are now ready to parse our first plenary protocol. Once the parser has been initialized, the user intervention that is required is minimal. The whole idea behind is to automate parsing plenary protocols, thus making the procedure reproducible.

The exception to this rule at this stage is that that the parser requires the metadata of the document to generate a telling header, but it does not (yet) have a method to extract the relevant information from the document. So we write a function $getMetadata() that does this, based on the original pdf document.

getMetadata <- function(filename){
  pdfdoc <- pdftools::pdf_text(pdf = doc)
  page1 <- strsplit(pdfdoc, "\n")[[1]]
  
  # get session
  docIdRegex <- "^.*?\\s*(A)\\s*/(\\d+)/\\s*(PV\\.\\d+).*?$"
  session <- do.call(rbind, gsubfn::strapplyc(X = page1, pattern = docIdRegex))[1,2]
  
  # get date
  weekdays = c("Monday", "Tuesday", "Wednesday", "Thursday", "Friday", "Saturday", "Sunday")
  months = c(
    January = 1, February = 2, March = 3, April = 4, May = 5, June = 6,
    July = 7, August = 8, September = 9, October = 10, November = 11, December = 12
    )
  dateRegex <- sprintf(
    "^\\s*(%s),\\s*(\\d{1,2})\\s+(%s)\\s+(\\d{4}),\\s+\\d{1,2}\\.\\d{2}\\s+(a\\.m\\.|p\\.m\\.)\\s*$",
    paste0(weekdays, collapse = "|"),
    paste0(names(months), collapse = "|")
  )
  dateMatch <- do.call(rbind, gsubfn::strapply(page1, pattern = dateRegex, c))
  year <- dateMatch[1,4]
  month <- as.integer(months[dateMatch[1,3]])
  day <- as.integer(dateMatch[1,2])
  dateOfMeeting <- sprintf("%s-%02d-%02d", year, month, day)
  
  # get meeting
  meetingRegex <- "\\s+(\\d+)(st|nd|rd|th)\\s+plenary\\s+meeting\\s*$"
  meeting <- do.call(rbind, gsubfn::strapplyc(page1, pattern = meetingRegex))[1,1]
  
  list(
    legislativePeriod = as.integer(session),
    sessionNo = as.integer(meeting),
    date = as.Date(dateOfMeeting),
    retrievalDate = "unknown",
    filetype = "pdf",
    url = "http://www.un.org/en/ga/",
    publisher = "United Nations",
    title = "Verbatim Records of the United Nations"
  )
}

Note that the original pdf document is the basis for getting the metadata: The metadata is found in regions that we wanted to get rid to have the clean text body.

metadata <- getMetadata(doc)

Let’s go. The first step is to read a file. We use the plain text file we used before.

PPP$readFile(filename = undoc_tmp, id = "A/71/PV.1")

Second. The initialized document includes some default metadata values: The birthdy the document was parsed , the package used (“frappp”) and the version of the package (see PPP$metadata). We add the metadata extracted before to these default metadata values.

PPP$addMetadata(data = metadata)

Third. We now generte the base TEI document by inserting the metadata into the TEI header. To do this, the parser uses the names of the character vector in the metadata to find matching XPath expressions in a character vector in the field xpath of the parser (PPP$xpath), using names. The respective XPath expression is used to find the correct place in the XML document for the piece of information of the metadata.

After running $makeHeader(), the field xml will contain the TEI document with the populated header (see PPP$xml, or cat(as.character(PPP$xml))).

PPP$makeHeader()

Third. The raw text (in the field PPP$txt) may include some noise. A preprocessing method ($preprocessin())will remove empty lines, and leading and trailing whitespace. It takes as input a list replacements, a list of length 2 character vectors that serve as input to gsub (parameters pattern and x, respectively), to perform usual cleanups.

PPP$preprocessing() # remove leading and and trailing spaces

Fourth. The essential feature of a plenary protocol is that it reports speech attributed to speakers. Indicating who is speaking is the organising principle of a protocol. So we use the regular expressions in the field PPP$speakerRegex to split up the (preprocessed) plain text into chunks of speech that will be kept (as a list) in the field $chunks.

PPP$splitBySpeakers()

If you look at any of these chunks (e.g. PPP$chunks[[2]]), you will see that the text has been extracted nicely from the pdf document, but that paragraphs have been destroyed.

Fifth: We reconstruct the paragraphs!

PPP$reconstructParagraphs(exclude = "pres")

See PPP$chunks[[2]] to see the result of this procedure. When reconstructing paragraphs, the heuristic is that lines are concatenated, when their length undercuts a standard length. To guess the number of characters per line that might be optimal, the method $showNcharHistogram() can be used.

Sixth. All preparatory steps have been performed. We now insert the speakers and the text of their speeches into the body of the XML document already present in the $xml field.

PPP$makeBody(agendaItems = TRUE)

That’s it! The XML document is in the $xml field of our class. You can either look at it by typing cat(as.character(PPP$xml)), if by using the convenience of a browser that is called with the $browseXML() method.

if (interactive()) PPP$browseXML()

To write the XML document to a file, you can use the following snippet.

outfile <- tempfile()
writeLines(text = as.character(PPP$xml), con = outfile)

This has been the verbose version of parsing a protocol. In real life, you certainly want things to be more efficient. So note that the implementation of the PlenaryProtocolParser meets the requirements to use a technique called method chaining, which is very similar to the pipes more commonly known in R.

PPP$readFile(filename = undoc_tmp, id = "A/71/PV.1")$
  addMetadata(data = getMetadata(doc))$
  makeHeader()$
  preprocessing()$
  splitBySpeakers()$
  reconstructParagraphs(exclude = "pres")$
  makeBody(agendaItems = TRUE)$
  saveXML(filename = tempfile())

Defining classes inheriting from PlenaryProtocolClass

  "VerbatimRecordUNGA",
  inherit = PlenaryProtocolParser,
  
  public = list(
    
    pdffile = NULL,
    
    initialize = function(){
      
      self$xpath = teiXpath
      
      self$speakerRegex <- list(
        pres = list(
          regex = "^(The\\s+President):\\s*(.+)$",
          fn = function(who, txt){
            c(
              who = who,
              state = "NA",
              role = "presidency",
              position = "presidency",
              text = txt

            )
          }

      )

        date = as.Date(dateOfMeeting),

        publisher = "United Nations",
        title = "Verbatim Records of the United Nations"
      )
    },

    xmlify = function(id, txtfile, pdffile, xmlfile, verbose = TRUE){
      if (verbose) message("... getting metadata")
      metadata <- self$getMetadata(pdffile)
      if (verbose) message("... reading plain text file: ", txtfile)
      self$readFile(filename = txtfile, id = id)
      if (verbose) message("... adding metadata that has beeen extracted")
      self$addMetadata(data = metadata)
      if (verbose) message("... making header")
      self$makeHeader()
      if (verbose) message("... preprocessing plain text")
      self$preprocessing()
      if (verbose) message("... splitting up by speakers")
      self$splitBySpeakers()
      if (verbose) message("... reconstructing paragraphs")
      self$reconstructParagraphs(exclude = "pres")
      if (verbose) message("... making body")
      self$makeBody(agendaItems = TRUE)
      if (verbose) message("... saving TEI document to file: ", teifile)
      self$saveXML(filename = xmlfile)
      invisible(self$xml)
    }
  )
)

Processing multiple documents

Usually, we want to process many protocols, not just one. Having prepared a class that is specialized to process a specific type of plenary protocol is the basis for moving to batch processing multiple documents. The following block of code may serve as an example how we might loop over multiple documents.

pdfdir <- tempdir()
txtdir <- tempdir()
xmldir <- tempdir()
txtFilesToProcess <- Sys.glob(paths = sprintf("%s/*.txt", txtdir))

UNGAParser <- VerbatimRecordUNGA$new()

lapply(
  txtFilesToProcess,
  function(txtfile){
    UNGAParser$xmlify(
      id = basename(txtfile),
      txtfile = txtfile,
      pdffile = file.path(pdfdir, gsub("^(.*?)\\.txt$", "\\1.pdf", basename(txtfile))),
      xmlfile = file.path(pdfdir, gsub("^(.*?)\\.txt$", "\\1.xml", basename(txtfile)))
    )
    return(TRUE)
  })
